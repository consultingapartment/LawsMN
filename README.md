# Монгол Улсын хуулийн сан (legalinfo.mn)

Хүчин төгөлдөр хууль, тогтоол, тушаалыг [legalinfo.mn](https://legalinfo.mn)-ээс татаж, цэвэр текст болгон хадгалж, SQLite санд бүртгэнэ.

| Код | Ангилал | Хавтас | Нэмэлт өөрчлөлт шалгах |
|---|---|---|---|
| 27 | Монгол Улсын хууль | `legal/` | сар бүр |
| 28 | Улсын Их Хурлын тогтоол | `uih_togtool/` | 3 сард нэг (ээлжилж) |
| 34 | Сайдын тушаал | `said_tushaal/` | 3 сард нэг (ээлжилж) |
| 33 | Засгийн газрын тогтоол | `zg_togtool/` | 3 сард нэг (ээлжилж) |

Шинэ ангилал нэмэхдээ `sync_laws.py` доторх `CATEGORIES`-д нэг мөр нэмж, `monthly.yml`, `sync-to-drive.yml`-д хавтсыг нь нэмнэ.

Сар бүр дахин ажиллахад:

- өмнө байгаагүй **шинэ баримт** гарвал татна
- «Нэмэлт өөрчлөлт» табын жагсаалт, эсвэл нэр/огноо/эмхэтгэл өөрчлөгдсөн бол тухайн баримтыг **дахин татна**
- жагсаалтаас алга болсныг устгахгүй, `inactive` гэж тэмдэглэнэ
- нэрэнд «ХҮЧИНГҮЙ БОЛСОНД ТООЦОХ» орсон актуудыг хасна

## Суулгах

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Ажиллуулах

```bash
python sync_laws.py                      # бүх ангилал
python sync_laws.py --category 27        # зөвхөн хууль
python sync_laws.py --category 28,34     # сонгосон ангилал
python sync_laws.py --time-budget 300    # 300 минутад зогсоож, дараа нь үргэлжлүүлнэ
python sync_laws.py --limit 5            # туршилт (ангилал бүрээс 5)
python sync_laws.py --metadata-only      # табыг шалгахгүй: зөвхөн шинэ + нэр/огноо өөрчлөгдсөн
python sync_laws.py --force              # бүгдийг дахин татах
```

Үр дүн:

| Файл | Агуулга |
|---|---|
| `data/laws.sqlite` | бүртгэл (`category` баганатай), өөрчлөлтийн түүх |
| `legal/*.txt`, `uih_togtool/*.txt`, … | текст (`{lawId}_{нэр}.txt`) |
| `data/last_sync.json` | сүүлийн синкийн товч, ангилал тус бүрээр |

Текстийг `POST https://legalinfo.mn/mn/wordExport` (`fileid`, A4 тохиргоо) хариунаас гаргаж авна. Энгийн GET линк хоосон загвар буцаадаг тул скрипт өөрөө татна.

`sync_events` хүснэгт: `new`, `updated`, `unchanged`, `missing`, `failed`, `check_failed` (табыг уншиж чадаагүй), `baseline`, `missing_guard`, `duplicate` (нэг баримт хоёр ангилалд гарсан).

## GitHub дээр сар бүр

`.github/workflows/monthly.yml` сар бүрийн 1-нд ажиллана. Repo → Settings → Actions → General дээр **Read and write permissions** нээх хэрэгтэй, эс бөгөөс commit push хийхгүй.

- Скрипт 300 минутад зогсож (`--time-budget 300`), хийснээ commit хийнэ.
- Дутуу үлдсэн бол (`"partial": true`) workflow өөрийгөө дахин эхлүүлж, тасарсан газраасаа үргэлжлүүлнэ. Эхний удаа ~9 000 тогтоол, тушаал татахад хэд хэдэн удаа дараалан ажиллана.
- Гараар ажиллуулахдаа **Run workflow** → `categories` талбарт `28` гэх мэтээр зөвхөн нэг ангилал сонгож болно.

`sync-to-drive.yml` нь синк амжилттай дууссаны дараа хавтас бүрийг Google Drive-ын тусдаа хавтас руу хуулна: `legal` → `LawsMN`, `uih_togtool` → `LawsMN_UIH_togtool`, `said_tushaal` → `LawsMN_Said_tushaal`, `zg_togtool` → `LawsMN_ZG_togtool`.

## Хэрхэн өөрчлөлт таньдаг вэ

1. Ангилал бүрийн идэвхтэй жагсаалтыг (`active=1`) бүхэлд нь уншина. Жагсаалт дуусаагүй эсвэл өмнөхөөс 10%-иас их буурсан бол сайтын доголдол гэж үзэж `inactive` болгохгүй.
2. `law_id` санд байхгүй бол **шинэ** — текстийг татна.
3. Нэр, огноо, эмхэтгэл өөрчлөгдсөн бол дахин татна.
4. Бусад үед «Нэмэлт өөрчлөлт» табын жагсаалтын хэшийг өмнөхтэй харьцуулна. Өөр бол дахин татна. Нэмэлт өөрчлөлтгүй баримтын хуудсанд таб байхгүй тул «0 нэмэлт» гэж тэмдэглэнэ — анх нэмэлт орох үед дахин татагдана.
5. Тогтоол, тушаалын ангилалд баримт бүрийг 3 сард нэг удаа (сар бүр гуравны нэгийг нь) шалгана. Ингэснээр сар бүрийн ажиллалт сайтыг хэт ачаалахгүй.
6. Табыг уншиж чадаагүй бол `check_failed` гэж бүртгэж, дараагийн удаа дахин шалгана.

Таб дээр шинэ мөр гараагүй засагдал (зөвхөн найруулгын засвар) энэ аргаар анзаарагдахгүй. Тийм үед `python sync_laws.py --force --category 27`.

Серверийг ачаалахгүйн тулд жагсаалтын хуудас хооронд 0.6 сек, таб шалгалт 0.35 сек, файл таталт 1.2 сек завсарлагатай.
